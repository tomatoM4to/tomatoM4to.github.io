## ARP 스푸핑
로컬에서 통신하고 있는 서버와 클라이언트의 IP 주소에 대한 2계층 MAC 주소를 공격자의 MAC 주소로 속인다. 클라이언트에서 서버로 가거나 서버에서 클라이언트로 가는 패킷을 공ㄱㄱ자에게 향하게 하고 공격자가 이 패킷을 읽으면 정상 목적지로 돌려보내 연결이 끊어지지 않도록 유지하는 공격이다. MAC 테이블의 static 설정을 통해 막을 수 있다.


## IP 스푸핑
트러스트 관계가 맺어진 서버와 클라이언트를 확인한 후 클라이언트에 DoS 공격을 하여 연결을 끊는다. 그런 다음 공격자가 클라이언트의 IP 주소를 확보해 실제 클라이언트처럼 패스워드 없이 서버에 접근하는 공격이다. 트러스트 관계를 쓰지 않는 것이 최상의 대첵이다.


## DNS 스푸핑
공격 대상이 특정 웹에 로그인을 할때는 도메인 이름으로 접근한다. 도메인 이름을 IP주소로 변환되어야 실제 접속이 가능해지므로 DNS서버에 도메인 이름에 대한 IP 주소를 물어본다. 이때 공격자는 도메인 이름에 대한 이름 해석 패킷, 즉 DNS Query 패킷을 탐지해 실제 DNS 서버보다 빨리 공격 대상에게 DNS Response 패킷을 보낸다. 그 결과 공격 대상이 잘못된 IP 주소로 이름 해석을 하도록 한다. 잘못된 웹 접속을 유도하는 공격으로 현재는 특별한 대책이 없다. hosts 파일에 중요 사이트의 IP 주소를 적어두면 그 사이트에 대해선 DNS 스푸핑 공격을 다하지 않는다.


## E-Mail 스푸핑
E-Mail의 도메인 주소는 임의의 시스템에 임의로 설정할 수 있으며, 계정 역시 해당 시스템에서 임의로 생성할 수 있다. 따라서 수신된 메일 계정 정보는 인증된 정보가 아닌 참조 정보로 이해해야 한다. 중요한 내용의 메일일 경우에는 전화와 같은 방식으로 다시 한 번 확인해야 한다.
