## 스푸핑
공격자가 자신의 신원이나 네트워크 정보를 다른 시스템의 정보처럼 위조하여 상대방을 속이는 방식

| 공격 | 위조 대상 | 계층 | 주요 목적 |
| :--- | :--- | :--- | :--- |
| ARP Spoofing | IP-MAC 대응 관계 | L2 | 패킷 가로채기 |
| IP Spoofing | 출발지 IP 주소 | L3 | 출발지 위장 |
| DNS Spoofing | DNS 응답 정보 | 응용 계층 | 잘못된 서버로 유도 |
| E-Mail Spoofing | 메일 발신자 정보 | 응용 계층 | 신원 사칭 및 피싱 |

## ARP 스푸핑
같은 LAN에 있는 시스템의 ARP캐시에 잘못된 IP-MAC 대응 관계를 저장하도록 속여, 네트워크 패킷이 공격자에게 전달되도록 만드는 공격

### 보안 대첵
* Static ARP
* DAI(Dynamic ARP Inspection)

> DAI는 IP-MAC매핑을 검사해 위조된 ARP 패킷을 차단 가능

## IP 스푸핑과 Trust
Trust Relationship이란 특정 시스템을 신뢰하여 일부 인증 절차를 생략하도록 설정한 관계를 말한다.

과거 `rlogin`, `rsh`같은 서비스에서 사용되었다.

시나리오
1. 서버가 특정 클라이언트의 IP 주소를 신뢰한다.
2. 공격자는 신뢰받는 클라이언트의 통신을 방해한다.
3. 출발지 IP주소를 신뢰받는 클라이언트의 주소로 위조한다.
4. TCP 연결 수립에 필요한 추가 조건까지 만족시키면 서버 접근을 시도할 수있다.

> 오늘날 DDOS 공격에서 출발지를 숨기거나 반사 공격을 유발하는 데이도 활용된다.

### 보안 대책
IP주소만으로 시스템을 인증하지 않고 SSH등의 암호확적 인증을 사용해야 한다. 추가로 라우터의 Ingress/Egress Filtering을 통해 비정상적인 출발지 IP를 가진 패킷을 차단할 수 있다.


## DNS 스푸핑
DNS응답을 위조하여 도메인 이름에 대응하는 IP주소를 잘못 알려주고, ㅅ용자를 공격자가 의도한 서버로 유도하는 공격

DNS 서버의 캐시를 오염시키는 DNS Cache Poisoning 방식도 존재

### 보안 대책
| 방어 기술 | 역할 |
| :--- | :--- |
| DNSSEC | DNS 데이터의 전자서명을 검증하여 위조 여부 확인 |
| DoH / DoT | 클라이언트와 DNS 리졸버 사이의 통신 암호화 |
| HTTPS / TLS | 잘못된 IP에 연결되더라도 서버 인증서 검증을 통해 사칭 탐지 |
| hosts 파일 | 특정 도메인의 IP 주소를 로컬에 고정 |

## E-Mail 스푸핑
공격자가 이메일의 발신자 정보를 위조하여 신뢰할 수 있는 사람이나 기관리 보낸 메일처럼 속이는 공격

이메일의 발신자 주소(From)는 메일 메시지의 헤더 정보로, 발신 시스템에서 임의로 지정할 수 있다. 따라서 수신된 이메일의 발신자 정보만으로 실제 발신자를 신뢰해서는 안된다.

* 공격자는 실제 이메일 계정을 탈취하지 않고도 발신자 정보를 위조하려고 시도할 수 있다.
* 위조된 메일을 이용해 피싱, 악성코드 배포, 계좌번호 변경 요청 등의 공격을 수행한다.
* 이메일 서버를 직접 해킹해야 하는 것은 아니다.

### 보안 대책
가장 기본적인 대응 방법은 계좌번호 변경, 송금 요청 등 중요한 내용의 이메일을 받았을 때 전화 등 별도의 신뢰할 수 있는 통신 수단으로 사실 여부를 확인하는 것이다.

과거에는 `@` 대신 `#`을 사용하는 샵메일(`#메일`) 제도가 도입되기도 했다. 일단 이메일과 호환성이 낮고 이용 절차가 복잡해 널리 정착하지 못했다.

현재는 `SPF`, `DKIM`, `DMARC`를 이용해 발신 도메인을 검증한다.

### 현대 이메일 스푸핑 방어 기술
| 기술 | 역할 | 핵심 |
| :--- | :--- | :--- |
| SPF (Sender Policy Framework) | 발송 서버 검증 | 허가된 IP인가? |
| DKIM (DomainKeys Identified Mail) | 전자서명 검증 | 서명이 유효한가? |
| DMARC (Domain-based Message Authentication, Reporting, and Conformance) | 도메인 정합성 검증 및 정책 적용 | 발신자 도메인을 신뢰할 수 있는가? |

그럼에두 불구하고 모든 형태의 발신자 사칭을 차단하는 것은 아니다.

### 표시 이름 스푸핑 (Display Name Spoofing)

실제 이메일 주소는 공격자의 주소이지만 수신자에게 표시되는 이름을 신뢰할 수 있는 조직이나 사람의 이름으로 변경하는 방식이다.

예를 들어 발신자가 `attacker@example.net`이지만 표시 이름이 `OO은행 고객센터`인 경우다.

### 유사 도메인 사칭 (Typosquatting)
정상 도메인과 철자가 비슷한 도메인을 등록하여 공격하는 방식이다.

예를 들어 `company.com` 대신 `cornpany.com`을 사용한다.

### 인증된 메일 서비스 악용
공격자가 정상적으로 인증된 외부 발송 서비스를 악용하거나, 허술하게 관리되는 하위 도메인 또는 탈취된 계정을 통해 악성 메일을 발송하는 방식이다.

이 경우 `SPF`, `DKIM`, `DMARC` 검증을 통과하더라도 메일 자체가 악의적일 수 있다.
