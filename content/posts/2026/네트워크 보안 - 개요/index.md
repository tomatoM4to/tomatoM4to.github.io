## 네트워크 보안의 요소
* **기밀성:** Server↔Client, Client↔Server, Client↔Client 의 통신에서 허락되지 않은 사용자 또는 객체가 정보의 **내용을 알 수 없도록** 한다.
  * 막기 위해선 암호화(TLS, IPsec 등)와 접근 제어 등을 사용한다. (교재에선 방화벽, 패스워드도 추가로 설명)
* **무결성:** 허락되지 않은 사용자 또는 객체가 전달되는 **정보를 수정할 수 없도록** 한다.
  * Hash는 데이터 변경 검출에 사용되며, 악의적인 변조에 대응하기 위해 HMAC이나 전자서명 등을 사용
* **가용성:** 허락된 사용자 또는 객체가 네트워크를 통해 정보에 **접근하려고 할 때 방해받지 않도록** 한다.
  * 대표적인 공격은 DDOS
* **서버 인증:** Client가 Server접근 시 해당 Server가 올바른 Server임을 확인한다.
* **클라이언트 인증:** Server에 접근하는 Client가 정당한 Client인지 확인한다.



## 프로토콜 3요소
* 구문(Syntax): 데이터의 구조나 포맷
* 의미(Semantics): 전송되는 데이터의 각 부분이 무엇을 뜻하는지 미리 정해둔 규칙 (오류 제어, 동기 제어, 흐름 제어를 포함)
* 순서(Timing): 통신 시스템과 망 사이의 속도나 순서 등을 정의

## 프로토콜의 기능
주소 설정, 순서 제어, 단편화 및 재조합, 캡슐화, 연결 제어, 흐름 제어, 오류 제어, 동기화, 다중화, 전송 서비스

## Cast
데이터를 누구에게 전달할 것인지, 즉 데이터의 전송 대상과 범위를 구분하는 방식

### Unicast
하나의 송신자가 특정 수신자 하나에게 데이터를 전달하는 방식
* 가장 일반적인 네트워크 통신 방식
* 목적지 IP또는 MAC주소로 대상을 식별
* TCP통신은 일반적으로 유니캐스트로 이루어짐

### Broadcast
하나의 송신자가 같은 브로드캐스트 도메인에 있는 모든 장치에게 데이터를 전달하는 방식

ARP가 개표적

> 일반적으로 라우터는 브로드캐스트를 다른 네티워크에 전달하지 않음

> IPv6에는 브로드캐스트가 없음, 멀티캐스트를 활용

### Multicast & Anycast
먼저 Group라는걸 이해야 한다. Group은 특정 목적을 위해 논리적으로 묶인 시스템들의 집합이다. 논리적이라 함은 같은 LAN에 있어도 그룹에 가입하지 않았으면 같은 Group에 참여하는 대상이 아니다.

대표적인 예시로 IPTV서비스가 있는데, 방송 송신자가 `239.1.1.1`이라는 멀티캐스트 IP주소에 영상을 송신한다 가정해보자, 가입자는 해당 주소에 가입하는 걸로 IPTV서비스를 이용할 수 있다. 반대로 탈퇴도 쉽게 가능

이중 Multicast는, 특정 그룹에 속한 여러 시스템들에게 전송

이중 Anycast는, 특정 그룹 속에 한 시스템에게만 전송

> 여러 시스템이 하나의 멀티캐스트 그룹 IP주소를 공유하는거지, 각 시스템의 고유 IP주소가 같아지는건 아니다.

> Anycast는 Group개념보단 동일 주소를 제공하는 서버들 간 라우팅이 좀더 정확한 설명




## 물리 계층 장비
* 리피터: 불분명해진 신호 세기를 증폭
* 허브: 물리 계층(L1)에서 동작하는 다중 포트 리피터로, 한 포트에서 수신한 신호를 다른 모든 포트로 전달한다.

> 전송 단위: Bit

## 데이터 링크 계층 프로토콜
흔히 LAN이라 부르는 네트워크 구간 또는 네트워크 하드웨어 사이에서 **MAC주소를 기반으로 통신**을 하기 위한 Ethernet프로토콜이 있다.

### 데이터 링크 계층 장비
* 브리지: 랜과 랜을 연결하는 네트워크 장치, 데이터 링크 계층에서 한 네트워크에서 다음 네트워크 선로를 따라 데이터 프레임을 복사하는 역할을 한다.
* **스위치:** LAN 내에서 MAC 주소를 기반으로 프레임을 전송

> Keyword: MAC주소, Frame단위, 스위칭, 오류검출

> 인접 노드간 흐름제어 및 오류제어도 수행한다.

### 스위칭
* **컷스루 방식:** 수신되는 프레임의 목적지 주소를 확인하고 목적지 주소의 포트로 프레임을 즉시 전송
* **저장 후 전송 방식:** 완전한 프레임을 수신해 버퍼에 보관했다가 전체 프레임을 수신하면 CRC등의 오류체크 후 정상 프레임을 목적지 포트로 전송
* **인텔리전트 스위칭 방식:** 컷스루 모드로 동작하다가 오류가 발생하면 저장후 전송 모드로 전환해 오류 프레임 전송을 중지하는 방식, 오류율이 0이 되면 다시 자동으로 컷스루로 전환
* **반이중 방식:** 양방향 통신이 가능하지만, 동시에는 불가능
* **전이중 방식:** 양방향 통신이 동시에 가능





## 네트워크 계층 프로토콜
* ARP: 통신 대상 시스템의 MAC주소를 알아내야 할 때 사용
* RARP: 자신의 MAC주소로부터 IP주소를 알아내야 할 때 사용
* IP: 논리적인 IP 주소를 이용하여 출발지에서 목적지까지 데이터그램을 전달하는 네트워크 계층 프로토콜
* ICMP: IP 네트워크에서 패킷 전달 중 발생하는 오류를 보고하고, 네트워크 연결 상태를 진단하는 프로토콜
* IGMP: 멀티캐스트에 관여하는 프로토콜로 멀티캐스트 그룹을 관리하는 역할을 수행

> Keyword: IP, ARP, Packet단위, Routing, 단편화

> 이론적 모델인 OSI7에선 해당 계층에서 흐름제어나 재전송을 수행한다고 흔히 알려져 있지만, 실제 인터넷 환경에선 수행되지 않는다.

### IP
목적지 IP주소를 기반으로 패킷을 전달하는 프로토콜

서로 다른 네트워크의 A와 B가 통신하기 위해 라우터를 거치며 통신한다. 이때 라우터는 내부의 라우팅 테이블을 이용하여 다음 전달 경로를 결정한다.

IP의 주요 특징은 다음과 같다.
1. 비연결형 통신 (Connectionless)
* 최선형 전달(Best Effort): 패킷 도착을 보장하지 않음
* IPv4에서는 필요에 따라 단편화 가능

### ARP
목적지 IP주소는 알고 있는데, MAC주소를 모를 때 사용하는 프로토콜, LAN 내부의 PC들끼리 MAC주소를 기반으로 통신하기 위해 사용한다.

동작 과정은 다음과 같다.

1. A가 같은 LAN에 있는 B의 주소를 알고 있다.
2. A가 ARP Request를 브로드캐스트한다.
3. B가 자신의 MAC주소를 ARP Reply 한다.
4. A는 그 MAC주소로 Ethernet 프로임을 전송한다.

> 중요한 점은 같은 LAN에서 사용할 MAC주소를 알아낸다는 점

> 다른 네트워크로 보낼 때는 최종 목적지의 MAC이 아니라, 일반적으로 게이트웨이의 MAC주소를 Reply 받는다.

> RARP는 그 반대, 과거 디스크 없는 컴퓨터가 부팅할 때 자신의 IP주소를 알아내는 용도로 사용, 현재는 거의 안쓰임

> ARP와 RARP메시지는 IP 패킷 안에 실리지 않는다. Ethernet 프레임에 직접 담기기 때문에 엄밀히 L3프로토콜이라고 단정하기는 어렵다. L2와 L3를 연결한다고 이해하면 된다.

### ICMP
크게 두 가지 목적으로 사용된다.

| 구분 | 역할 | 대표 메시지 |
| --- | ---- | --------- |
| 오류 보고 | 패킷 전달 실패나 문제 상황 알림 | `Destination Unreachable`, `Time Exceeded` |
| 정보 및 진단 | 네트워크 연결 상태 확인 | `Echo Request`, `Echo Reply` |

동작 순서는 다음과 같다.

### 네트워크 계층 장비
**라우터**

IP주소로 목적지
라우터는 논리적으로 분리된 둘 이상의 네트워크를 연결하는 역할을 한다. 로컬 네트워크에서 브로드캐스트를 차단해 네트워크를 분리하는 역할도 수행한다.

### 정적 라우팅과 동적 라우팅
**정적 라우팅**
* 관리자 권한으로 특정 경로를 통해서만 패킷이 지날 수 있도록 설정한 것이다.
* 라우팅 알고리즘을 통한 경로 설정이 이루어지지 않기 때문에 라우터의 직접적인 처리 부하가 감소
* 네트워크 환경 변화에 능동적인 대처가 어려움
* 네트워크 환경 변화 시 관리자가 새로운 라우팅 정보를 통해 경로를 재산출해 각각의 라우터에 제공해야 함
* 비교적 환경 변화가 적은 형태의 네트워크에 적합

**동적 라우팅**
* 라우터가 네트워크 연결 상태를 스스로 파악해 최적의 경로를 선택해 전송하는 방식
* 경로 설정이 실시간으로 이루어지기 때문에 네트워크 환경 변화에 능동적인 대체가 가능
* 라우팅 알고리즘을 통해 자동으로 경로 설정이 이루어지기 때문에 관리하기 쉬움
* 주기적인 라우팅 정보 송수신으로 인한 대역폭 낭비를 초래함
* 네트워크 환경 변화 시 라우터에 의한 경로 재설정으로 라우터의 처리 부하가 증가하고 지연이 발생
* 수시로 환경이 변화는 형태의 네트워크에 적합


## 전송 계층 프로토콜

> Keyword: Segment, 흐름제어, 오류제어

> Application과 Transport 계층은 End System에서 수행된다.

> Port를 구분한다.

### TCP
전송 계층에서 동작하는 연결형 프로토콜로, 데이터의 흐름을 관리하고 데이터가 정확한지 검증하며 통신함, 3-Way handshake를 통해 연결을 설정함

### UDP
UDP는 비연결형 전송 프로토콜로, TCP와 달리 데이터의 전달 및 순서를 보장하지 않는다. Checksum을 통한 오류 검출 기능은 있지만 자체적인 재전송 및 흐름 제어는 제공하지 않는다.
