## Sniffing
네트워크를 통해 전송되는 패킷을 수집하고 분석해난 행위(도청)

네트워크 관리와 문제 해결에도 사용하지만, 공격자가 패킷을 가로채 민감한 정보를 수집하는 데 악용할 수도 있다.

중요하게 다뤄질 장비는 Hub와 Switch가 있다.
* Hub: 수신한 신호를 다른 모든 포트에 전달, 패킷 수집이 비교적 쉬움
* Switch: MAC 주소 테이블을 이용해 목적지 포트로 전달하므로 다른 장치 사이의 유니캐스트 패킷을 직접 수집하기 어려움

따라서 공격자는 스위칭 환경에서 패킷을 가로채기 위해 `ARP Spoofing`, `ICMP Redirect`, `MAC Flooding` 등 의 기법을 사용할 수 있다.

## Promiscuous Mode
NIC 이 자신의 MAC 주소가 목적지가 아닌 이더넷 프레임 도 수신하도록 허용하는 모드

| 구분 | 일반 모드 | Promiscuous Mode |
| --- | -------- | ---------------- |
| 자신의 MAC으로 온 프레임 | 수신 | 수신 |
| 브로드캐스트 프레임 | 수신 | 수신 |
| 다른 MAC으로 온 프레임 | 일반적으로 필터링 | 수신 가능 |
| 주요 용도 | 일반 통신 | 패킷 분석 및 모니터링 |

> 모드를 활성화한다고 스위치의 모든 패킷을 볼 수 있는 것은 아니다. 스위치가 해당 포트로 전달하지 않은 프레임까지 NIC이 가져올 수는 없기 때문, 즉 받은 프레임을 필터링 하지 않는 기능

## 스위칭 환경에서의 스니핑 공격

| 공격 기법 | 계층 | 핵심 원리 |
| -------- | --- | -------- |
| ARP Spoofing | L2 | IP-MAC 매핑을 위조 |
| ARP Redirect | L2 | 공격자를 게이트웨이로 오인시킴 |
| ICMP Redirect | L3 | 라우팅 경로 변경을 유도 |
| Switch Hamming | L2 | MAC 주소 테이블 고갈 유도 |
| SPAN / TAP | 주로 L2 | 트래픽 복사 및 수집 (미러링) |

### ARP Spoofing 과 ARP Redirect
ARP Spoofing은 위조된 ARP 메시지를 보내 다른 시스템의 ARP 캐시에 잘못된 IP-MAC 매핑을 저장하도록 만드는 공격이다.

예를 들어 실제 게이트웨이의 정보가 다음과 같다고 해보자.
* 게이트웨이 IP: `192.168.0.1`
* 실제 MAC: `AA:AA:AA`
* 공격자 MAC: `BB:BB:BB`
공격자는 피해자에게 `192.168.0.1`의 MAC 주소가 `BB:BB:BB`라고 속일 수 있다.

ARP Redirect는 ARP Spoofing의 한 유형으로, 공격자가 자신을 게이트웨이처럼 보이게 하여 외부로 향하는 패킷을 가로채는 방식이다.

### ICMP Redirect
IP 라우팅 정보를 변경하도록 유도한다.

ICMP Redirect는 원래 라우터가 호스트에게 더 적절한 다음 Hop을 알려주는 정상적ㅇ니 기능이다. 공격자는 이를 악용해 위조된 ICMP Redirect 메시지로 피해자의 경로 변경을 시도할 수 있다.

다만 OS가 실제로 변경하는지는 OS의 ICMP Redirect 수용 정책에 따라 달라진다.

### Switch Jamming
스위치의 MAC 주소 테이블을 대량의 가짜 MAC 주소로 채우는 공격이다.

테이블이 고갈되면 목적지 MAC을 학습하지 못한 유니캐스트 프레임이 여러 포트로 Flooding 될 수 있다. 다만 스위치가 완전히 허브로 변하는건 아니고, 현대 스위치는 Port Security 등으로 이런 공격을 제한할 수 있다.

### SPAN / TAP
이 둘은 본래 공격 기법이 아니라 네트워크 관리를 위한 패킷 수집 수단이다.
* **SPAN(Port Mirroring):** 스위치가 특정 포트나 VLAN의 트래픽을 분석용 포트에 복사하는 기능.
* **TAP(Network TAP):** 통신 경로에 설치해 트래픽을 복제하는 하드웨어 장치.


## 스니핑 탐지 방법
### Ping을 이용한 탐지
1. 스니핑이 의심되는 호스트의 실제 IP 주소를 지정한다.
2. 이더넷 프레임의 목적지 MAC 주소는 해당 호스트의 MAC과 다르게 설정한다.
3. 정상 NIC이라면 해당 프레임을 필터링 해야 한다.
4. 그런데 ICMP Echo Reply가 돌아온다면 Promiscuous Mode 가능성을 의심할 수 있다.

> IP는 맞지만 MAC이 틀린 패킷을 보내보는것

### ARP를 이용한 탐지
Ping과 비슷하지만 ARP Request를 이용한다.

정상적으로는 무시되어야 할 이더넷 프레임에 ARP Request를 넣고, 의심 호스트에 이에 응답하는지 확인하는 방식이다.

> Ping과 ARP 모두 과거에 사용된 휴리스틱 탐지 방식이며, 현대에는 신뢰성이 낮을 수 있다.

### DNS를 이용한 탐지
일부 스니핑 프로그램은 패킷의 출발지나 목적지 IP를 발견하면 해당 IP의 호스트명을 알아내기 위해 역방향 DNS 조회(PTR)을 수행한다.

이런 조회가 예상하지 못한 IP에 대해 발생한다면 스니퍼가 동작하고 있다는 단서가 될 수 있다.

### TCP를 이용한 탐지
Ping 탐지와 유사하게 목적지 MAC을 비정상적으로 지정한 TCP 패킷을 보내고 TCP RST 등의 응답을 확인하는 방법이 있다.

> 이 방법도 네트워크 스택 동작에 의존하며 확정적인 방법은 아니다.

### ARPWatch
IP와 MAC의 대응 관계를 지속적으로 관찰하다가 게이트웨이의 MAC 주소가 갑자기 변경되는 등의 상황을 확인하는 거다.

즉 Promiscuous Mode 자체보다 ARP Spoofing으로 발생하는 비정상적인 주소 매핑을 탐지하는 데 적합하다.

## 보안 대책과 암호화
* `TLS`: HTTPS등 네트워크 통신 데이터 보호 (SSL의 후속 기술)
* `PGP / OpenPGP`: 이메일 등 데이터의 암호화 및 전자서명
* `S/MIME`: 인증서 기반의 이메일 암호화 및 전자서명
* `PEM`: 역사적으로 사용된 이메일 보안 표준
* `SSH`: 원격 접속과 명령 실행 등을 암호화
* `VPN`: 암호화 기능을 갖춘 VPN 프로토콜을 사용해 네트워크 터널 보호
