## 보수 표현

## Shift

```asm
LSL Rd, Rs, n  ; 왼쪽으로 n비트
LSR Rd, Rs, n  ; 오른쪽으로 n비트

ASL Rd, Rs, n  ; LSL과 동일함
ASR Rd, Rs, n  ; 정수에 대해 부호가 바뀌지 않음
```

Rs의 비트들을 n비트 왼쪽이나 오른쪽으로 이동한 값을 Rd에 저장하는 연산이다. 왼쪽으로 이동시키는건 별거 없고, 큰 차이는 오른쪽으로 shift할경우 부호를 결정짓는 최상위 비트가 바뀌면서 부호가 바뀔수 있기 때문

* `LSL`, `LSR`, `ASL`: 빈자리를 0으로 채운다.
* `ASR`: 빈자리를 기존 **최상위 비트와 동일한 값**으로 채운다.

먼저 8비트 정수 `-4`로 왜 오른쪽 시프트시 차이가 발생하는지 알아보자.

1. `1111 1100` → -4 (8비트 2의 보수)
2. `LSR 2`
3. `0011 1111` → 63 (부호가 바뀜)

만약 `ASR 2`를 할경우 `1111 1111` 가 되면서 `-1`이 된다. (부호 유지)

> 이해를 돕기 위한 예시로, 실제 TOY에선 32비트 정수를 처리함

왼쪽으로 시프트하는 `LSL`과 `ASL`은 서로 다른 명령어지만 실제 비트 연산은 동일하다, 그저 **논리적 시프트와 산술적 시프트를 개념적으로 구분하기 위해**서 이렇게 2개가 있는것

* `LSL`: 부호를 고려하지 않는 비트 이동이라는 의미
* `ASL`: 부호 있는 정수에 대한 산술적 연산이라는 의미

> 개념적이기 때문에 ASL을 사용해도 최상위 비트가 바뀔 시 부호가 바뀐다.

> LSL, LSR, ASL, ASR은 모두 연산 결과에 따라 CCR의 N, Z 비트를 갱신한다.

## Shift를 이용한 곱셈

십진수 `123`을 왼쪽으로 시프트하고 빈자리를 `0`으로 채우면 `1230`이 된다. 정확히 10배

이걸 응용하면 곱셈을 효율적으로 처리할 수 있다.

예를들어 `0000 1100`에 대해서 왼쪽으로 2비트 이동시 (`LSL 2`), 값은 `0011 0000`이 되고 값은 12에서 48로 $\times4$가 된다.

| 명령어 | 연산 효과 | 12를 기준으로 |
| ----- | -------- | ----------- |
| `LSL 1` | $\times2$ | 24 |
| `LSL 2` | $\times4$ | 48 |
| `LSL 3` | $\times8$ | 96 |
| `LSL 4` | $\times16$ | 192 |

### $\times10$

$10 = 8 + 2 = 2^3 + 2^1$

```asm
.ORIGIN 0x2000
  LOAD R1, value

  LSL R2, R1, 3    ; R2 = value x 8
  LSL R3, R1, 1    ; R3 = value x 2
  ADD R1, R2, R3   ; R1 = value x 10

  STORE R1, result
  SWI 255

value:  .FILL 12
result: .BLOCK 1
```

> TOY에서 곱셈을 구현하기 위해 숫자만큼 반복 더하는 방식과 위처럼 시프트를 이용한 방식 2가지가 있다.

## Shift를 이용한 나눗셈

반대로 오른쪽으로 이동하면 각 비트의 자릿값이 절반으로 줄어들기 떄문에 2로 나누는 효과가 있다.

```text
원본       0000 1100 = 12

LSR 1      0000 0110 = 6
LSR 2      0000 0011 = 3
LSR 3      0000 0001 = 1

원본       0000 1101 = 13
LSR 2      0000 0011 = 3
```

> 나누어 떨어지지 않는 경우에는 소수점 아래 부분이 버려진다 라고 이해하면 된다. (0 이상의 정수에 한해서)

### mod
$2^n$으로 나눌 경우 오른쪽으로 n비트 이동하면 몫을 얻을 수 있고, 하위 n비트만 AND 마스킹으로 남기면 나머지를 구할 수 있다.

예를들어 $123 \div 8$를 계산하려면 ASM 코드는 다음과 같이 작성할 수 있다.

```asm
.ORIGIN 0x2000
  LOAD R1, value

  ASR R2, R1, 3
  STORE R2, quot

  AND R3, R1, 7
  STORE R3, remain

  SWI 255

value:  .FILL 123
quot:   .BLOCK 1
remain: .BLOCK 1
```

이진수로 살펴보면 왜 가능한지 이해할 수 있다.

1. 123의 이진수 `0111 1011`
2. 오른쪽으로 세자리 이동 = `0000 1111`
3. `0111 1011` AND `0000 0111` = `0000 0011`

결과적으로 몫은 `0000 1111`, 나머지는 `0000 0011` 이 된다.

> 위 관계는 곱셈에서 오버플로가 없고, 나눗셈과 나머지는 0이상의 정수를 다룬다는 전제가 있다.

## Example
R1에 20이 들어있다 가정해보자
```asm
LSL R2, R1, 2  ; 80 → 20 x 4
ASR R3, R1, 2  ; 5  → 20 / 4
AND R4, R1, 3  ; 0  → 20 % 4
```

## Addressing Mode

Register에 저장된 값은 단순한 데이터일 수도 있고 **메모리 주소** 일수도 있다. 마치 C언어의 Pointer처럼 메모리로부터 값을 읽어오는 명령어가 ASM에 존재한다.

| 예시 | 의미 |
| `COPY R1, 10` | 정수 10을 직접 사용 |
| `COPY R1, R2` | R2의 값을 사용 |
| `LOAD R1, x` | x주소에 저장된 값을 읽음 |
| `LEA R1, x` | x의 주소를 읽음 |
| `LDR R1, R2, offset` | R2+offset 을 메모리 주소로 사용하여 해당 위치에 저장된 값을 R1에 읽어옴 |
| `STR R1, R2, offset` | R1의 값을 R2+offset 이 가리키는 메모리에 저장 |

> `LDR`과 `STR`의 offset은 16비트 정수이며 레지스터를 직접 지정할 수 없다.

### LOAD와 LEA의 차이

```asm
.ORIGIN 0x2000
  LOAD R1, x  ; R1 ← M[x]
  LEA R2, x   ; R2 ← x의 주소
  SWI 255

x:  .FILL 42
```
> `M[x]`는 메모리의 x번지에 저장된 내용을 뜻

해당 프로그램을 `ORIGIN`을 기준으로 조소를 배치하면 다음과 같아진다.

```text
0x2000  LOAD R1, x
0x2001  LEA R2, x
0x2002  SWI 255
0x2003  x: .FILL 42
```

그리고 R1와 R2에는 다음과 같은 값이 들어온다.
* **R1: 42**
* **R2: 0x2003**

### LDR과 STR (레지스터 간접 어드레싱)
```asm
LDR R1, R2, offset   ; R1 ← M[R2 + offset]
STR R1, R2, offset   ; M[R2 + offset] ← R1
```
> offset: 기준 주소에 더할 정수

가령 R2에 `5000`이 저정되어 있고 메모리 `5003`번지에 77이 있다면 `LDR R1, R2, 3` 실행수 R1에는 77이 들어가게 된다.

## Pointer의 구현

다음 코드는 ASM으로 이렇게 변환이 가능하다.
```c
int x = 10, y;
int *p = &x;

*p = 99;
y = *p;
```

```asm
.ORIGIN 0x2000

; int *p = &x;
LEA R1, x     ; R1 = 0x2009
STORE R1, p   ; M[0x200B] = 0x2009

; *p = 99;
COPY R3, 99
LOAD R1, p    ; R1 = 0x2009
STR R3, R1, 0 ; M[0x2009] = 99

; y = *p;
LOAD R1, p    ; R1 = 0x2009
LDR R2, R1, 0 ; R2 = M[0x2009] = 99
STORE R2, y   ; M[0x200A] = 99

SWI 255

x: .FILL 10   ; 0x2009
y: .BLOCK 1   ; 0x200A
p: .BLOCK 1   ; 0x200B
```
> C언어의 Pointer나 Type은 어셈블리 수준에서 직접 구분되지 않는다.

## Array의 구현
C언어의 배열은 ASM에선 이렇게 표현할 수 있다.

```text
C
int arr[4];

ASM
arr: .BLOCK 4
```
> TOY에선 주소 하나가 데이터 하나를 나타내므로 a[i]주소는 `a의 시작주소 +i` 로 나타낼 수 있다.


### 고정된 인덱스 접근

```C
arr[2] = 22;
x = arr[2];
```
```asm
LEA R1, arr
COPY R2, 22
STR R2, R1, 2   ; a[2] = 22

LDR R3, R1, 2   ; R3 = a[2]
STORE R3, x

SWI 255

arr: .BLOCK 4
x: .BLOCK 1
```

### 변수로 인덱스 지정하기

```C
int i = 2;
arr[i] = 99;
```
```asm
LEA R1, arr
LOAD R2, i
ADD R1, R1, R2

COPY R3, 99
STR R3, R1, 0

SWI 255

arr: .BLOCK 4
i: .FILL 2
```

### 배열 순회와 반복문

```C
int arr[4] = {10, 20, 30, 40};
int sum = 0;

for (int i = 0; i < 4; i++) {
  sum += arr[i];
}
```

```asm
.ORIGIN 0x2000

  LEA R1, arr
  COPY R2, 0  ; sum
  COPY R3, 4  ; 반봇 횟수

loop:
  LDR R4, R1, 0
  ADD R2, R2, R4   ; sum += a[i]

  ADD R1, R1, 1    ; 다음 원소로 이동
  SUB R3, R3, 1    ; 남은 반복 횟수 감소
  BR p, loop

  STORE R2, sum
  SWI 255

arr:
  .FILL 10
  .FILL 20
  .FILL 30
  .FILL 40
sum:
  .FILL 0
```

## BRR과 BR
`BRR`은 레지스터에 저장된 주소를 기반으로 분기하는 명령어다. 이를 통해 실행 중 결정되는 주소로 이동하거나, 직접 어드레싱의 16비트 상대 주소 범위를 벗어난 위치로 분기할 수 있다.

**사용**
```asm
  LEA R1, target
  BRR nzp, R1, 0

target:
  SWI 255
```

`target`주소로 분기한다. 단, `BRR`은 해당 메모리의 내용을 읽어오는 것이 아니라 계산한 주소 자체를 PC에 기록하는 명령어다.

굳이 `BRR`이 필요한 이유는, TOY의 한계 떼문인데, TOY 명령어는 32비트이기 때문에 주소를 포함한 모든 정보를 32비트에 표현해야 하기에, `LOAD`, `STORE`, `LEA`, `BR`은 실제 기계어에서 PC를 기준으로 한 16비트 상대주소를 사용한다.

접근 가능한 범위는 다음과 같다.

$
PC-32768 \leq addr \leq PC+32767
$

이런 경우 가까운 메모리 위치에 먼 주소를 저장해 두고, 해당 주소를 레지스터로 읽은 뒤, `LDR`, `STR`, `BRR` 등으로 접근할 수 있다.
